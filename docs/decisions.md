# Design decisions (and where they depart from CLAUDE.md)

Made while building W1–W12 unattended. Each was argued for/against before choosing; the losing option is noted.

| # | Decision | Why | Rejected alternative |
|---|---|---|---|
| 1 | **Explainer is deterministic** (AST → English), not LLM. *Departs from CLAUDE.md §4 "Explainer — LLM".* | The readback is the human's last check before Approve; it must be faithful to every clause and cannot invent behaviour. Tests prove every clause of 64 policies is covered. | LLM readback: more fluent, but can silently misdescribe the policy. An optional LLM "polish" can be added later on top. |
| 2 | **Scenarios are split into independent vs characterization.** Independent = from the user or an LLM that sees only the English rules (never the YOG). Characterization probes (boundaries, no-context) are shown as *unconfirmed* and **excluded from the pass %**. | Expected values copied from the engine always "pass"; counting them would be circular and falsely green. | One merged score (simpler, but misleading). |
| 3 | **Modifier inserts a `@yog_guard("tool")` decorator** + one import, instead of rewriting call sites. | Zero removed lines (tested), survives async/sync/methods, keeps signatures so FastMCP still sees parameters. Runtime ships as a standalone file next to `yog.py` and `policy.yog`. | Wrapping each call site (touches many lines, brittle). |
| 4 | **One fact-normalisation path** (`app/core/facts.py`, mirrored in `yog_runtime.py`, equality tested). | Raw values crash or mis-lex in the engine (floats, `True`, `"USD"` lexes as a variable). | Normalising separately in runtime, simulator and evaluator (drift). |
| 5 | **Engine `TypeError` ⇒ fail closed (DENY).** Logged as engine issue #7. | A guardrail must never turn an engine crash into a 500 or an ALLOW. | Letting it propagate. |
| 6 | **C engine = placeholder with no invented ABI**; selecting `YOG_ENGINE=c` without a library is an error. | The C engine has no published interface; guessing one would be fake work. Conformance suite is ready for it. | A fake C adapter that delegates to Python (misleading). |
| 7 | **Prepared demo policy is hand-written and labelled as such** in the UI. | Offline (fake LLM) the translator only echoes the nearest example; the demo must not pass that off as translation. | Presenting the echo as a generated policy. |
| 8 | **Approval gate is server-side and evidence-based**: `/policies/approve` re-validates, runs its own evaluation (client-supplied evaluation ignored), and the UI keeps Approve disabled until scenarios were run for the *current* text. | CLAUDE.md §3.1: results before the Approve click; never trust the client. | Trusting a client "valid" flag. |
| 9 | Devices and bundles use **only approved policies** (`store.latest()` / explicit id); guard-off mode exists for the demo contrast and is labelled UNGUARDED. | A draft must never govern a device. | Using the current draft. |
| 10 | Tests force the fake LLM (`conftest.py`), the LLM is a FastAPI dependency. | A `.env` with a real key must never make the suite call (and bill) Gemini. | Reading the provider from the environment in tests. |
| 11 | **Compiler first, Studio second.** The landing page leads with a live compiler explorer; Studio is the workbench around it. *Departs from CLAUDE.md §2, which frames Studio as the product.* | The graded story is the YOG compiler. Studio exists to write YOG faster. | Studio as the headline product. |
| 12 | **The public site is written as if the engine were complete**, but states no invented numbers and shows only what the live engine computes. `docs/claims-ledger.md` + `scripts/claims_check.py` list every statement that still has to become true. | Owner's call for the final demo. The ledger keeps the gap visible to the team. | A status/roadmap section on the site. |
| 13 | **Explorer = Python reference + the engine team's real C lexer, side by side.** The C lexer is vendored at a pinned commit, built in CI and in the Docker image, and degrades to "unavailable" when missing. | It is the only C stage with a published verification report. A C parser dump tool does not exist yet. | Presenting a C pipeline that is not wired. |
| 14 | **LLM calls are cached, rate-limited, and behind one interface.** Gemini first, Claude second, embeddings from Gemini. Output is JSON-schema constrained where the API supports it, with a prompt-only fallback. | Free-tier limits make the benchmark grid slow; reproducibility needs a cache. | Calling the API directly from each module. |
| 15 | **A draft is only `verified` against scenarios written from the English alone, by a model that never sees the YOG.** `verified` never approves anything; the human click stays mandatory. | Scenarios copied from the draft's own behaviour would always pass. | Treating "compiles" as "correct". |
| 16 | **Evaluation hygiene**: frozen test split (hash-assigned, new rules default to dev), prompt/dataset hashes, Wilson intervals, offline-fake results kept in `results/fake/` and never served by `/benchmark`. | A handful of rules cannot support bare percentages; fake runs measure retrieval echo, not translation. | One headline accuracy figure. |
| 17 | **Rules and scenarios drafted by Claude are marked `claude-draft`** until a teammate reviews them (`app.benchmark.review`). A revision that fails the item's own scenarios is refused. | CLAUDE.md §11: benchmark rules must be written by humans. | Presenting drafted data as team-written. |
| 18 | **Motion is measured, not claimed**: every behaviour carries `data-motion`, `e2e/motion.mjs` counts them, the user can pause everything, and OS reduced-motion is honoured. | "10x the motion" needs a definition that can fail. | A subjective "more animation". |
| 19 | **"Fix with AI" was not built.** Friendly errors apply deterministic one-click fixes only; Assist drafts from English. | An LLM rewriting a broken program is a second, unverifiable authoring path next to the Assist flow. | A model-powered repair button. |
| 20 | **Retrieval is strict.** Only examples whose embedding similarity clears a per-model floor (calibrated on held-out paraphrases and off-topic queries, `benchmark/retrieval_floors.json`) are shown to the AI; a draft with none is marked **ungrounded** and needs a second explicit confirmation (UI and server). | Weak matches presented as "similar solved examples" mislead the model and the user. Gemini floor 0.754: keeps 99.1% of correct matches, rejects 100% of 20 off-topic queries. | Always returning the top 3. |
| 21 | **The keyword (BM25) fusion I added was measured and rejected.** The embedding decides; the keyword weight defaults to 0 (`RETRIEVAL_LEX_WEIGHT`). Tool names only nudge the ranking and are no longer mixed into the query or the embedded text. | On 109 reworded rules, fusing keywords lowered recall for both embedders (Gemini recall@1 99.1% at weight 0 → 83.5% at weight 1; offline 85.3% → 80.7%). Tool names in the query made off-topic rules that mention a tool look relevant. | Hybrid retrieval as planned. |
| 22 | **The retrieval eval no longer hands each paraphrase its own example's tool names** (opt-in `oracle_tools`). | That hint flattered the numbers (offline recall@3 97.2% with it, 89.9% without, same code). | Reporting the flattering figure. |
| 23 | **Real AI / Offline is a per-request switch**, not a server restart. Real needs a key and passes a per-client rate limit plus a daily budget (`LIVE_LLM_DAILY_CAP`); `ALLOW_LIVE_LLM=0` turns it off for a deployment. Offline is always available and never pretends to translate. | A public site must not let visitors spend the operator's quota; the choice must be visible and reversible. | A server-wide env var only. |
| 24 | **Citations are checked, not trusted.** The model must end its reply with `USED_EXAMPLES:`; ids it cites that were never in the prompt are reported as problems. The optional LLM reranker only ever reorders and falls back to the search order on any failure. | A claimed source that does not exist is worse than none. | Free-text "based on" claims. |
| 25 | **The marketing pages are black and gold, with a three.js point-cloud globe in the hero.** An orb of ~14,000 gold dots (rim-lit, shadowed lower right, back side drawn faintly, with a sparse halo shell at 1.3x radius) holds a **logo core**: ~9,000 dots shaped like the letters "YOG" and spread through the depth of the ball. Nothing rearranges; the orb turns, so side-on the core is a bright band and front-on it reads as the letters. It swings from side-on to front-on on landing, then turns slowly; drag turns it with inertia, hover dents the skin and lets a few (48) dots come loose and float around the pointer, only while it is over the orb; a click sends a ripple and a burst of debris. The ground is pure black with the existing grid and the floating connected dots. Studio (`.studio-dark`) keeps its navy look. | The reference the owner chose (motion.dev) is a layered dot orb with a logo core on black. My first version scattered dots and rearranged them into letters, which is not what the reference does; the technique was re-derived from the reference's public bundle (behaviour and structure only) and the shaders and geometry here are written from scratch. Re-pointing Tailwind's `sky` ramp at gold inside `.mkt` recolours the marketing pages in one place and cannot leak into Studio. A static gold wordmark replaces the globe without WebGL, and pause / OS reduced motion show one still frame with the logo formed. | A 2D-canvas globe (lighter, but the owner asked for three.js); recolouring Studio too. |
| 26 | **Two WebGL contexts are allowed on the landing page** (the hero globe and the decision gate), up from one. The gate only mounts when its section is within 500 px of the viewport and the globe stops drawing off-screen or in a hidden tab. | Browsers allow many contexts; the risk is first-paint GPU load, which lazy mounting removes. | Rebuilding the gate as part of the globe. |

Numbers above are from `retrieval_eval` on `benchmark/paraphrases.yaml`. Both the examples and the paraphrases are `claude-draft`
(same author), so these figures are an upper-bound sanity check until the team's human-written holdout exists (decision 17).
