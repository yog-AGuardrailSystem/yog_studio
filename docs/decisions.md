# Design decisions (and where they depart from CLAUDE.md)

Made while building W1–W12 unattended. Each was argued for/against before choosing; the losing option is noted.

| # | Decision | Why | Rejected alternative |
|---|---|---|---|
| 1 | **Explainer is deterministic** (AST → English), not LLM. *Departs from CLAUDE.md §4 "Explainer — LLM".* | The readback is the human's last check before Approve; it must be faithful to every clause and cannot invent behaviour. Tests prove every clause of 64 policies is covered. | LLM readback: more fluent, but can silently misdescribe the policy. An optional LLM "polish" can be added later on top. |
| 2 | **Scenarios are split into independent vs characterization.** Independent = from the user or an LLM that sees only the English rules (never the YOG). Characterization probes (boundaries, no-context) are shown as *unconfirmed* and **excluded from the pass %**. | Expected values copied from the engine always "pass"; counting them would be circular and falsely green. | One merged score (simpler, but misleading). |
| 3 | **Modifier inserts a `@yog_guard("tool")` decorator** + one import, instead of rewriting call sites. | Zero removed lines (tested), survives async/sync/methods, keeps signatures so FastMCP still sees parameters. Runtime ships as a standalone file next to `yog.py` and `policy.yog`. | Wrapping each call site (touches many lines, brittle). |
| 4 | **One fact-normalisation path** (`app/core/facts.py`, mirrored in `yog_runtime.py`, equality tested). | Raw values crash or mis-lex in the engine (floats, `True`, `"USD"` lexes as a variable). | Normalising separately in runtime, simulator and evaluator (drift). |
| 5 | **Engine `TypeError` ⇒ fail closed (DENY).** Logged as engine issue #7. | A guardrail must never turn an engine crash into a 500 or an ALLOW. | Letting it propagate. |
| 6 | **(Superseded by #46.) C engine = placeholder with no invented ABI**; selecting `YOG_ENGINE=c` without a library is an error. | The C engine has no published interface; guessing one would be fake work. Conformance suite is ready for it. | A fake C adapter that delegates to Python (misleading). |
| 7 | **Prepared demo policy is hand-written and labelled as such** in the UI. | Offline (fake LLM) the translator only echoes the nearest example; the demo must not pass that off as translation. | Presenting the echo as a generated policy. |
| 8 | **Approval gate is server-side and evidence-based**: `/policies/approve` re-validates, runs its own evaluation (client-supplied evaluation ignored), and the UI keeps Approve disabled until scenarios were run for the *current* text. | CLAUDE.md §3.1: results before the Approve click; never trust the client. | Trusting a client "valid" flag. |
| 9 | Devices and bundles use **only approved policies** (`store.latest()` / explicit id); guard-off mode exists for the demo contrast and is labelled UNGUARDED. | A draft must never govern a device. | Using the current draft. |
| 10 | Tests force the fake LLM (`conftest.py`), the LLM is a FastAPI dependency. | A `.env` with a real key must never make the suite call (and bill) Gemini. | Reading the provider from the environment in tests. |
| 11 | **Compiler first, Studio second.** The landing page leads with a live compiler explorer; Studio is the workbench around it. *Departs from CLAUDE.md §2, which frames Studio as the product.* | The graded story is the YOG compiler. Studio exists to write YOG faster. | Studio as the headline product. |
| 12 | **The public site is written as if the engine were complete**, but states no invented numbers and shows only what the live engine computes. `docs/claims-ledger.md` + `scripts/claims_check.py` list every statement that still has to become true. | Owner's call for the final demo. The ledger keeps the gap visible to the team. | A status/roadmap section on the site. |
| 13 | **Explorer = Python reference + the engine team's real C lexer, side by side.** The C lexer is vendored at a pinned commit, built in CI and in the Docker image, and degrades to "unavailable" when missing. | It is the only C stage with a published verification report. A C parser dump tool does not exist yet. | Presenting a C pipeline that is not wired. |
| 14 | **LLM calls are cached, rate-limited, and behind one interface.** Gemini first, Claude second, embeddings from Gemini. Output is JSON-schema constrained where the API supports it, with a prompt-only fallback. | Free-tier limits make the benchmark grid slow; reproducibility needs a cache. | Calling the API directly from each module. |
| 15 | **A draft is only `verified` against scenarios written from the English alone, by a model that never sees the YOG.** `verified` never approves anything; the human click stays mandatory. | Scenarios copied from the draft's own behaviour would always pass. | Treating "compiles" as "correct". |
| 16 | **Evaluation hygiene**: frozen test split (hash-assigned, new rules default to dev), prompt/dataset hashes, Wilson intervals, offline-fake results kept in `results/fake/` and never served by `/benchmark`. | A handful of rules cannot support bare percentages; fake runs measure retrieval echo, not translation. | One headline accuracy figure. |
| 17 | **Rules and scenarios drafted by Claude are marked `claude-draft`** until a teammate reviews them (`app.benchmark.review`). A revision that fails the item's own scenarios is refused. | CLAUDE.md §11: benchmark rules must be written by humans. | Presenting drafted data as team-written. |
| 18 | **Motion is measured, not claimed**: every behaviour carries `data-motion`, `e2e/motion.mjs` counts them, the user can pause everything, and OS reduced-motion is honoured. | "10x the motion" needs a definition that can fail. | A subjective "more animation". |
| 19 | **"Fix with AI" was not built.** Friendly errors apply deterministic one-click fixes only; Assist drafts from English. | An LLM rewriting a broken program is a second, unverifiable authoring path next to the Assist flow. | A model-powered repair button. |
| 20 | **Retrieval is strict.** Only examples whose embedding similarity clears a per-model floor (calibrated on held-out paraphrases and off-topic queries, `benchmark/retrieval_floors.json`) are shown to the AI; a draft with none is marked **ungrounded** and needs a second explicit confirmation (UI and server). | Weak matches presented as "similar solved examples" mislead the model and the user. Gemini floor 0.754: keeps 99.1% of correct matches, rejects 100% of 20 off-topic queries. | Always returning the top 3. |
| 21 | **The keyword (BM25) fusion I added was measured and rejected.** The embedding decides; the keyword weight defaults to 0 (`RETRIEVAL_LEX_WEIGHT`). Tool names only nudge the ranking and are no longer mixed into the query or the embedded text. | On 109 reworded rules, fusing keywords lowered recall for both embedders (Gemini recall@1 99.1% at weight 0 → 83.5% at weight 1; offline 85.3% → 80.7%). Tool names in the query made off-topic rules that mention a tool look relevant. | Hybrid retrieval as planned. |
| 22 | **The retrieval eval no longer hands each paraphrase its own example's tool names** (opt-in `oracle_tools`). | That hint flattered the numbers (offline recall@3 97.2% with it, 89.9% without, same code). | Reporting the flattering figure. |
| 23 | **Real AI / Offline is a per-request switch**, not a server restart. Real needs a key and passes a per-client rate limit plus a daily budget (`LIVE_LLM_DAILY_CAP`); `ALLOW_LIVE_LLM=0` turns it off for a deployment. Offline is always available and never pretends to translate. | A public site must not let visitors spend the operator's quota; the choice must be visible and reversible. | A server-wide env var only. |
| 24 | **Citations are checked, not trusted.** The model must end its reply with `USED_EXAMPLES:`; ids it cites that were never in the prompt are reported as problems. The optional LLM reranker only ever reorders and falls back to the search order on any failure. | A claimed source that does not exist is worse than none. | Free-text "based on" claims. |
| 25 | **The marketing pages are black and gold, with a three.js point-cloud globe in the hero.** An orb of ~14,000 gold dots (rim-lit, shadowed lower right, back side drawn faintly, with a sparse halo shell at 1.3x radius) holds a **logo core**: ~9,000 dots shaped like the letters "YOG" and spread through the depth of the ball. Nothing rearranges; the orb turns, so side-on the core is a bright band and front-on it reads as the letters. It swings from side-on to front-on on landing, then turns slowly; drag turns it with inertia, hover dents the skin and nudges the 96 dots nearest the pointer by a few pixels, only while it is over the orb; a click sends a ripple and a burst of debris. The ground is pure black with the existing grid and the floating connected dots. Studio (`.studio-dark`) keeps its navy look. | The reference the owner chose (motion.dev) is a layered dot orb with a logo core on black. My first version scattered dots and rearranged them into letters, which is not what the reference does; the technique was re-derived from the reference's public bundle (behaviour and structure only) and the shaders and geometry here are written from scratch. Re-pointing Tailwind's `sky` ramp at gold inside `.mkt` recolours the marketing pages in one place and cannot leak into Studio. A static gold wordmark replaces the globe without WebGL, and pause / OS reduced motion show one still frame with the logo formed. | A 2D-canvas globe (lighter, but the owner asked for three.js); recolouring Studio too. |
| 26 | **Two WebGL contexts are allowed on the landing page** (the hero globe and the decision gate), up from one. The gate only mounts when its section is within 500 px of the viewport and the globe stops drawing off-screen or in a hidden tab. | Browsers allow many contexts; the risk is first-paint GPU load, which lazy mounting removes. | Rebuilding the gate as part of the globe. |
| 27 | **"Studio" opens a tool hub (`/studio`), not the workbench.** The hub uses the landing look (`MarketingLayout`) and lists every tool from one registry (`frontend/src/lib/tools.ts`): purpose, three-step "how it works", what it does not do, and Open. Tools not built yet are shown as "Not built yet" with no link. The workbench moved to `/studio/workbench`; old `/studio#p=...` share links forward there. | Evaluators should see the whole product and pick a path; adding a tool is one registry entry plus one route. Listing unbuilt tools as planned is honest and the count line is checked by a test. | Keeping the workbench as the Studio home with a side menu. |
| 28 | **The Why-Explainer replays every allow/deny clause itself and is checked against `check()` on every call.** It uses the engine's own `rename`, `unify_atom` and `solve` (no engine edit) to show, for each clause, whether it matched or at which condition and with which values it stopped. If its verdict ever differs from `check()`, the page shows `check()`'s answer and hides the explanation. | `Engine.check` returns a trace only for the winning clause and nothing for a default deny, so "why was this denied?" had no answer. An explanation that could contradict the engine would be worse than none. | Reading `check()`'s trace (empty exactly when the question is hardest). |
| 29 | **Gap findings say whether they are *proved* or a *heuristic*; coverage is "unknown" without the agent's tool list.** Proved = follows from the text (dead range, shadowed allow, duplicate, deny-only action, tool with no rule). Heuristic = a probe or rule of thumb (fails open without context, unused fact, rule no probe reaches). | A list of warnings that mixes certainty with guesses trains people to ignore it. "100% of tools covered" with no tools known was a real bug the tests found. | One flat list. |
| 30 | **Red-Team judges against promises the user states, never against the engine's own output.** Without promises it lists only ALLOWs that look unexpected and says nothing is confirmed. Hours, arguments and numbers named by a promise are attacked even when the policy never mentions them. | A tool that calls an output "wrong" without a stated intent is circular. A policy that ignores the hour is exactly the bug a night-time promise must catch (found by the tests). | Auto-labelling "suspicious" rows as failures. |
| 31 | **Test Strength is mutation testing over the policy text**: flip a comparison, shift a number, drop a condition or a rule, remove a `not`; keep edits that compile; a scenario that the unchanged policy already fails cannot judge. Capped at 40 edits. With no scenarios it uses generated probes and labels the score as measuring those probes only. | It scores the *tests*, which nothing else in Studio does. Survivors may be harmless equivalents, so the page says the score is a guide. | Coverage alone (does not show whether a test would notice a change). |
| 32 | **The audit log is a per-visitor JSONL file where each line carries the hash of the previous one.** Bounded (2,000 lines; the oldest 500 go and their last hash becomes the anchor). Best effort: a failed write never blocks a device command. CSV cells starting with `= + - @` are neutralised. | It makes edits, deletions and reordering detectable without a database. It does not prevent them, and it is not long-term storage; the page says both. | In-memory only (the old device log grew without bound). |
| 33 | **The runtime guard decides one call at a time (lock), can pin the policy (`YOG_POLICY_SHA256`, line endings ignored), can log decisions (normalised values only) and has `--selftest`.** | The engine adds and removes request facts on shared state, so concurrent calls could see each other's facts. A pin turns "someone edited policy.yog after approval" into a DENY. CRLF-insensitive because an editor or git re-saving the file must not lock the agent out. | No lock; hashing raw bytes. |
| 34 | **More agent frameworks are recognised from the AST only**: LangChain `@tool`, OpenAI Agents SDK `@function_tool`, CrewAI `@tool("name")`, PydanticAI `@agent.tool`. A framework counts only when its package is imported and a function carries its decorator. The guard goes directly above `def`, under the framework's decorator. | Matching a bare `@tool` would flag unrelated files. Insertions only, as before. | Matching decorator names alone. |
| 35 | **Approved-policy ids can no longer collide.** Ids are a timestamp to the second plus a hash of the text; saving identical text twice in one second overwrote the first record (found while testing Restore). The store now moves the timestamp on until the id is free. | "Versions are never edited" must be true. | Adding a random suffix (changes the id format that other code validates). |
| 36 | **The rate-limit key is the proxy-appended right-most `X-Forwarded-For` address, validated as an IP; anything else falls back to the socket peer.** | The left-most entry is written by the client: rotating it gave a fresh bucket per request, naming a victim drained the victim's bucket, and long values filled the key table (security audit, `session-xff-rate-limit-spoof`). Right-most is correct whether the proxy appends or overwrites; it assumes one trusted hop. | Trusting the left-most entry; `--proxy-headers`. |
| 37 | **Write requests with `Transfer-Encoding` are refused (411), and a malformed `Content-Length` is a 400.** | The 1.5 MB cap read only the `Content-Length` header, so a chunked body skipped it and was buffered whole (`protect-body-cap-content-length-only`). Browsers always send a length. | Counting bytes in a pure-ASGI middleware (more code; no client needs chunked uploads). |
| 38 | **The live-AI protections follow the provider, not the `mode` flag.** A live server-default provider (`LLM_PROVIDER=gemini|claude`) now passes the same kill switch, per-client limit and daily budget as `mode=real`, on `/translate`, `/retrieve` and `/evaluate`. Translate rules are capped at 2,000 characters each and tool text is truncated before it reaches a prompt. | With a live default, omitting `mode` skipped all three controls (`live-guard-bypass-default-provider-mode`); a request was charged one unit however much text it carried. The shipped `LLM_PROVIDER=fake` was never affected. | Guarding only `mode=real`. |
| 39 | **Engine evaluation has a work budget enforced in the adapter, not in `engine/yog.py`.** `_bounded()` counts goal evaluations per decision (400,000) and caps the trace; over budget is DENY ("failing closed"). Policy parsing is cached per distinct text. `/check`, `/evaluate`, `/explain` and `/policies/approve` get the same 200,000-character cap as the Studio tools; `/evaluate` takes at most 200 scenarios. | A non-recursive policy can still enumerate exponentially many proofs (`engine-evaluation-unbounded-work-and-memory`). The vendored engine is not edited (CLAUDE.md), so the budget wraps `Engine.solve` per instance. The budget is generous for real policies (a few hundred steps). Report to the engine team as an upstream request. | Editing the engine; a wall-clock thread (cannot kill a Python thread). |
| 40 | **Smaller bounds and fixes from the same audit.** GET never creates a device simulator for an unknown session; device arguments are at most 12 keys and 200 characters; the all-zero fallback session id is not accepted as a cookie and the id regex uses `\Z`; the Gap Analyzer's shadow check has a necessary-condition prefilter and a step cap; Test Strength builds mutant text lazily (at most 2,000 sites); probe generators expand at most 60 argument keys; `backend/data/` is git-ignored. | Each was a finding or a confirmed hardening note (`device-sim-lru-eviction-by-cookieless-get`, `device-command-args-unbounded-sim-log-and-audit`, `studio-gaps-shadows-exponential-backtracking`, `studio-mutation-generate-materialises-all-mutant-sources`, `redteam-candidates-list-materialised-before-budget`). | Per-session byte quotas (not done; see the audit report). |
| 41 | **Decimals and path-like values are refused, not rounded or merged.** A decimal argument (28.4) or text containing `/`, `\` or `..` makes the guard, the device simulator, Trace Replay and the SDK tester return DENY ("refused, failing closed"). Whole floats (22.0) still work. Studio and the runtime copy raise the same message (a test enforces it). | Owner decision after the audit (`facts-float-rounding-bypasses-numeric-bounds`, `facts-ident-collapses-distinct-paths-allowlist-bypass`): rounding let 28.4 pass `temperature <= 28`, and ident() merged `../notes.txt`, `/notes.txt`, `NOTES.TXT`. | Rounding down/up; keeping paths as exact quoted strings (the lexer cannot express them). Limitation: exact-path allowlists are not supported. |
| 42 | **Polish from the audit.** (a) Disk quota: 10 MB per visitor (`SESSION_MAX_BYTES`) and 500 MB for all visitors (`SESSIONS_MAX_BYTES`); only new policy saves are refused (HTTP 507), expired sessions are cleaned once before refusing. (b) The `/api/docs`, `/api/redoc` and `/api/openapi.json` pages are removed in production (`app.asgi`). (c) Public `/status` shows only ok/degraded, engine and live-ready; usage numbers need the `X-Status-Token` header matching `STATUS_TOKEN`. (d) Gemini errors use fixed wording; the upstream body is never relayed. (e) Monaco is bundled (`src/lib/monacoSetup.ts`, `monaco-editor` pinned), so the CSP has no CDN. | Owner chose all four after the audit. Quota stops disk-fill by anonymous visitors; docs and `/status` numbers helped probing; upstream text can echo request content; a CDN script is a supply-chain dependency. | Quota per file type; a login for `/status`; keeping the CDN (needs `script-src` to trust a third party). Cost: the build now ships about 16 MB of Monaco files (loaded on demand). |
| 43 | **The /studio hub is five 3D boxes; each opens to show its tools as cards.** The scene (`components/hub/HubScene.tsx`, three.js, lazy chunk) only draws. Real buttons and links sit over it and are moved each frame onto the projected shape (`HubOverlay`), so keyboard, touch, screen readers and tests work without picking inside WebGL. No WebGL, `?fx=off` or a scene error shows the same flow on plain tiles; reduced motion removes the camera flight. The per-tool explanations stay below the stage. The top-left YOG monogram opens a product About panel (not team credits). State is `lib/hubModel.ts` (unit-tested); an open box is `/studio#box=<group>` so Back works. | The reference design (a 3D box of cards, an About reveal on the monogram) shown by the owner; gold on black to match the landing page. | Picking cards in WebGL with a raycaster (no keyboard or screen-reader path); `@react-three/drei` (not installed, three.js alone was enough); a CSS-only 3D version (cannot do the lid and camera). |
| 44 | **Hub scene rebuilt to match the reference cabinet.** Lacquered cabinets with real wall thickness, a hinged lid with a smoked-glass inside, hinges, a lit plug, cable and beam; tools as thin glass cards (own line icon each, `lib/hubIcons.ts`) standing like files; a dark mirror floor (`Reflector`), bloom, and our own dim studio environment for reflections. 3/4 view measured from the recording (azimuth 47°, elevation 29°). The label under the stage scrambles in on every hover. Card click: rises out of its slot, turns to the camera and fills the screen before the tool opens. Quality tiers: `?fx=high|medium|low`; phones start low, slow frames step down. Bright light sources and glows are kept out of the mirror (layer 1). Animations use real elapsed time, so slow machines finish them on time. Fix found on the way: pressing Back while a tool page was still loading left the hub frozen mid-flight (popstate now resets it). | Owner compared the first version with the recording and asked for a faithful replica. | `drei`/`postprocessing` packages (three.js addons were enough); RoomEnvironment (its bright panels made hot spots in the mirror). |
| 45 | **One black-and-gold look everywhere, and labels that scramble.** Tool pages re-pointed from dark blue to black and gold by changing only the `.studio-dark` colour variables (slate inverted and warm, sky/blue ramps to gold; ALLOW green and DENY red kept), Monaco theme warm black; every button and link scrambles its label on hover or focus and settles on the exact original (`lib/hoverScramble.ts`: one delegated listener, keeps an `aria-label` with the real text meanwhile, stops if React changes the text, off in calm motion); gold cursor site-wide (inline SVG, allowed by the CSP); hub: grey floor haze like the reference, cabinets that turn slightly all the time (still under the cursor), bigger, faster gold motes pushed away by the cursor. | Owner review of the hub on the local server. | Editing 33 pages one by one; per-component scramble wrappers. |
| 46 | **The C engine is called as a subprocess (`yogc batch`), not through ctypes.** *Departs from CLAUDE.md §4 ("via ctypes").* Policy text is written once to a temp file (cached by SHA-256, 16 entries); a whole scenario list goes through one process (`check_many`); every failure (crash, 5 s timeout, wrong answer count, a VM error) is a DENY, never an ALLOW and never a fallback to Python. | Upstream builds static libraries only; a C crash must not take the backend down; it matches the existing `lexdump` bridge. Owner decision, Nov 2026. | ctypes over a shared library (none exists); a Python fallback when C fails (a guardrail must not quietly run on another engine). |
| 47 | **Context facts are parsed and re-serialised before they reach C, and unsafe values are refused.** C turns every `;` into a newline even inside quotes, so an argument value could add an authority fact (engine_issues #11). | Each item must be exactly one ground fact (same check as the Python adapter); values containing `"` `\` `;` `|` or control characters are DENY. | Escaping (C has no escape syntax); trusting callers (the alpha's stance). |
| 48 | **C decides, the reference parser explains.** The C API has no AST, predicate table or explain call, so the workbench's structure, the explainer and the Why panel come from the Python reference parser; `explain()` refuses to show a proof (error "engines disagree") when C's decision differs. `/info` reports "decisions: C · structure: reference parser". Docker/CI default to `YOG_ENGINE=c`; local dev stays `python`. | The Why panel must never explain a decision C did not make. | Showing the Python proof next to a C decision regardless. |
| 49 | **Use C wherever Studio decides, cheaply and visibly.** The Studio tools batch their checks (`safe_check_many`: one `yogc` process per policy, the same answers and budget accounting as row-by-row); plain queries are answered by C (bindings from the agreeing reference, #21); the workbench has a C IR tab; the benchmark takes `--engine`; decision screens say which engine decided; the shipped runtime guard can opt in with `YOG_YOGC` (Python stays the default there, so a downloaded agent needs no C toolchain). | On C, one process per check made Test Strength and the Scorecard take ~5 s on the demo policy (now ~0.2-0.5 s). Owner chose opt-in for the runtime. | A long-running yogc server process (more moving parts); shipping C sources in the export pack (users would need a compiler). |
| 50 | **yogc is downloadable from Studio's own /download page, built in the Docker image.** A `dist` stage cross-compiles `yogc.exe` with mingw-w64 and a static Linux `yogc` from the vendored engine, and wraps Windows in an NSIS installer built on Linux (per-user install, no admin; PATH added and removed safely, refusing to edit a PATH too long to read back whole); also a zip and a tarball, with SHA-256 sums. The backend serves only manifest-listed names. Verified under Wine: yogc.exe decides correctly; silent install adds files, Start-menu entries, Installed-apps entry and PATH; uninstall restores PATH exactly. | Owner chose: built in Docker and served by Studio, a real installer, Windows + Linux. The download then always matches the engine Studio runs, with no extra accounts or release process. | GitHub Releases (separate place, needs tags; the engine team may still publish there later); Inno Setup/WiX (Windows-only tools); code signing (costs money, or an open-source program like SignPath; noted on the page instead).

Numbers above are from `retrieval_eval` on `benchmark/paraphrases.yaml`. Both the examples and the paraphrases are `claude-draft`
(same author), so these figures are an upper-bound sanity check until the team's human-written holdout exists (decision 17).
